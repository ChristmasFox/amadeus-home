# 9Router managed model capabilities

## Logical image capability (model-capability adapter candidate)

`infra/9router/model-capabilities.json` is the Git desired state for the
`kind=image` `amadeus-image` Combo: `strategy=fallback` with
`ag/gemini-3.1-flash-image` first and `cx/gpt-image-2.5` second. OpenClaw
references only `openai/amadeus-image`; it does not retry concrete models.
The existing 9Router management API is used through the shared protected
loopback client in `scripts/nine_router_management.py`. No 9Router source,
image, provider connection, credential, account, OAuth record, or ASR/TTS
alias is changed by this provisioning operation.

```sh
python3 scripts/checkpoint-amadeus-model-capability.py      # no host write
python3 scripts/provision-9router-image-combo.py              # no auth/write
python3 scripts/checkpoint-amadeus-model-capability.py --apply --machine nyannyan
python3 scripts/provision-9router-image-combo.py --apply \
  --machine nyannyan \
  --checkpoint-dir /Volumes/Avalon/backups/operation-skuld/amadeus-model-capability
python3 scripts/provision-9router-image-combo.py --verify-live --machine nyannyan
# Independent rollback of only this Combo/strategy from the printed 0600 path:
python3 scripts/provision-9router-image-combo.py --apply \
  --machine nyannyan --restore-checkpoint /protected/path/amadeus-image-preapply-...json
```

Apply refuses an existing wrong-kind Combo or conflicting alias. It reconciles
only model order and the per-Combo fallback strategy, then reads back the
result. The external protected snapshot holds only the previous Combo identity,
kind/order, and this Combo's fallback-setting presence/value—never provider
settings or credentials. A second apply makes no API mutation. The normal OpenClaw deployment
requires `--verify-live` to pass before switching images. No 9Router restart
is required. Production transport and fallback-path checks are distinct
acceptance gates. `python3 scripts/smoke-9router-image.py` is plan-only unless
`--apply` is provided; it sends one prompt-only image request from the live
OpenClaw network and discards generated bytes in memory.
`python3 scripts/verify-9router-image-fallback.py --machine nyannyan`
injects synthetic 429/503 failures into the exact compiled live 9Router image
Combo helper without
changing providers/accounts or sending a paid request. A safe live first-model
fault is not induced by these tests. The pinned helper also treats an upstream
HTTP 400 as fallback-eligible; route-level missing-prompt validation returns
400 before Combo dispatch. Do not claim a general no-fallback guarantee for
upstream client errors without a separate 9Router change, which is outside
this Goal. Reference-image editing parity is not claimed.
