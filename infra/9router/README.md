# 9Router managed model capabilities

## Amadeus image capability

`infra/9router/model-capabilities.json` is the Git desired state for the
`kind=image` `amadeus-image` Combo: `strategy=fallback` with
`cx/gpt-image-2.5` as its only native 9Router model. OpenClaw references only
`openai/amadeus-image`. OpenClaw owns the local Qwen fallback after eligible
operational primary failures; safety refusals and invalid requests are
terminal. Keep Qwen out of the native 9Router Combo so fallback ownership stays
single and explicit. Reference edits preserve the original image through the
primary path and use the OpenClaw-owned local edit path only when eligible.
The existing 9Router management API is used through the shared protected
loopback client in `scripts/nine_router_management.py`. Combo provisioning
does not change 9Router source, image, provider connections, credentials,
accounts, OAuth records, or ASR/TTS aliases.

```sh
python3 scripts/checkpoint-amadeus-model-capability.py      # no host write
python3 scripts/provision-9router-image-combo.py              # no auth/write
python3 scripts/checkpoint-amadeus-model-capability.py --apply --machine nyannyan
python3 scripts/provision-9router-image-combo.py --apply \
  --machine nyannyan \
  --checkpoint-dir /Volumes/Avalon/backups/operation-skuld/amadeus-model-capability
python3 scripts/provision-9router-image-combo.py --verify-live --machine nyannyan
# Independent rollback of only this Combo/strategy from the printed 0600 path:
python3 scripts/provision-9router-image-combo.py --apply \
  --machine nyannyan --restore-checkpoint /protected/path/amadeus-image-preapply-...json
```

Apply refuses an existing wrong-kind Combo or conflicting alias. It reconciles
only model order and the per-Combo fallback strategy, then reads back the
result. The external protected snapshot holds only the previous Combo identity,
kind/order, and this Combo's fallback-setting presence/value—never provider
settings or credentials. A second apply makes no API mutation. The normal OpenClaw deployment
requires `--verify-live` to pass before switching images. No 9Router restart
is required. Production transport and fallback-path checks are distinct
acceptance gates. `python3 scripts/smoke-9router-image.py` is plan-only unless
`--apply` is provided; it sends one prompt-only image request from the live
OpenClaw network and discards generated bytes in memory.
`python3 scripts/verify-9router-image-fallback.py --machine nyannyan`
injects synthetic 429/503 and safety-refusal failures into the exact compiled
live 9Router image Combo helper without changing providers/accounts or sending
a paid request. These tests do not induce a live primary fault.

## Source-preserving upgrades

The current candidate pins npm `9router@0.5.95` over the immutable upstream
Docker base digest in `infra/docker/casaos/9router/Dockerfile`. Our 9Router
modifications remain source-controlled: the image-account policy, terminal
safety guard, and self-hosted TTS style patch live in the adjacent `patch-*.mjs`
files and are applied during image build. Each patch checks the package version
and/or unique compiled anchors; upstream drift fails the build rather than
silently dropping a modification.

Do not update npm inside the running container or hand-edit its compiled
bundles. `scripts/deploy-9router.sh` builds from `git archive HEAD`, so only
committed source is included. Its explicit `--apply --build` path exports the
old immutable image outside Git, creates a protected database/Compose/env
checkpoint, runs the candidate in an isolated fixture, changes only the
9Router service, and verifies health/auth/config with automatic Compose
rollback on failure. Run `scripts/deploy-9router.sh --dry-run` first; do not
deploy until the intended source commit and focused tests are ready.
