# 9Router speech adapter — 1.5.3 candidate

9Router remains the sole model/provider control plane. The companion `asr-bridge.mjs` is a bounded transport adapter for Alibaba Model Studio's synchronous Qwen-Audio-3.0-ASR-Flash multimodal-generation contract, **not** an Agent or second router. It listens on container loopback `127.0.0.1:20129`, never publishes a host port, and returns OpenAI-compatible `{ "text": ... }` to 9Router's Self-hosted STT provider. `amadeus-asr` must be an alias for `selfhosted-stt/qwen-audio-3.0-asr-flash`, not the old Chat Combo. TTS uses 9Router Self-hosted TTS -> M204 port 18792 and `amadeus-tts` -> `selfhosted-tts/qwen3-tts-1.7b/kurisu-v1`.

## Protected runtime files (never commit values)

- Guest `/DATA/AppData/9router/secrets/asr-bridge-key`: generated by `scripts/prepare-9router-speech-secrets.sh --apply`; uid 1000 (container `node`), mode 0600. A protected Mac copy is used for 9Router connection provisioning.
- Guest `/DATA/AppData/9router/secrets/dashscope-asr-api-key`: operator-provided Model Studio key, uid 1000, mode 0600.
- Guest `/DATA/AppData/9router/9router.env`: `AMADEUS_DASHSCOPE_ASR_URL=https://<workspace>.<region>.maas.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation` for the key's matching region. Preserve the existing API-key, proxy and other settings; no value or workspace identifier belongs in Git.
- M204 `~/Library/Application Support/Amadeus/speech/tts.token`: existing local TTS token for the Self-hosted TTS connection.
- A protected dashboard-password file on M204 for one-time `scripts/provision-9router-speech.py --apply`; no password goes on a command line or into Git.

## Gates and rollback

1. `pnpm workflow:plan`, focused tests and `pnpm check:secrets`.
2. `scripts/export-9router-runtime.sh --apply` exports the old image to Avalon. `scripts/test-9router-speech-image.sh --image <immutable-tag> --apply` boots an isolated **network-none fixture** and checks Node 22, ffmpeg, authenticated ASR conversion and the normalized unavailable category. Fixture data and keys are removed afterward. A fresh fixture DB may not enforce the production API-key gate; the deployment smoke checks the live preserved setting returns 401.
3. `scripts/deploy-9router-speech.sh` is dry-run by default. `--apply` requires clean Git and the protected files, writes a consistent SQLite + Compose/env/secrets checkpoint under `/DATA/AppData/9router/backups/`, builds an ARM64 immutable commit-tagged image, loads it to the OrbStack `nyannyan` guest, applies canonical Compose with `--no-build` and checks both health endpoints and API-key protection. A failed health smoke restores the old Compose/image; preserve the checkpoint for manual data restore. No default live operation runs on macOS host Docker.
4. Provision 9Router connections/aliases with `scripts/provision-9router-speech.py` **only after** a direct real DashScope smoke. That script takes another protected SQLite checkpoint before retiring the conflicting Chat Combo. Direct 9Router `/v1/audio/transcriptions` and `/v1/audio/speech` tests, OpenClaw deployment, failure/fallback and real WhatsApp acceptance remain separate gates.

Bridge caps: 7 MiB multipart input, 6 MiB converted mono 16 kHz WAV (about three minutes), 80 s upstream timeout, 30 s conversion timeout, no retry, max 128 successful transcript entries held in memory for five minutes. No private audio, transcripts, tokens or full provider errors are logged. A TTS service outage does not stop this independent ASR process. The 9Router container has a supervisor for the bridge and packaged server; if either exits the container restarts under CasaOS. No secret asset or production voice source is in the image.
