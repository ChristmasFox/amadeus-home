# PUBG V3.2 — Rollback Runbook

## Safety Rules

- Only touch the `pubg-query-engine-v3` CasaOS app and the explicitly installed `local/pubg-stats` artifact.
- Do not delete `/DATA/AppData/pubg-query-engine-v3/data`, `pubg_cache`, V2 workflows or the V3.1 snapshot.
- Rollback runs inside OrbStack `ubuntu`, never on host Docker.
- Preserve the current compose and state before changing image/plugin references.

## Engine Rollback

1. Inspect the accuracy-patch backup or the V3.1 backup and choose the intended image/parser-feature pair.
2. Restore the intended `image:` and, when rolling back parser semantics, the matching `PUBG_TELEMETRY_PARSER_VERSION` and `PUBG_REVIEW_FEATURE_VERSION` values in `/var/lib/casaos/apps/pubg-query-engine-v3/docker-compose.yml`.
3. Recreate the CasaOS app:

```bash
orb -m ubuntu -u root bash -lc 'cd /var/lib/casaos/apps/pubg-query-engine-v3 && docker compose up -d'
```

4. Verify `docker ps`, container health and `curl http://127.0.0.1:5310/healthz`.
5. Keep the V3.2 Feature Store backup and data files. The old engine can ignore new review files; restore them only if a specific V3.1 state snapshot requires it.

## Plugin Rollback

Use LangBot's normal plugin management to restore the V3.1 `local/pubg-stats` artifact/source from the LangBot backup. If the LangBot runtime image itself must be restored, use the recorded `langbot-local:4.10.8-kook-fix-ssh7` image and recreate only the LangBot CasaOS app.

Do not manually remove the currently installed package before the replacement is available. Verify `/pubg`, ordinary PUBG Query, and the V2 fallback path after the switch.

## Feature Store Recovery

The compacted Feature Store is the current compatible format for V3.2. To recover the pre-compaction file, stop the engine, copy the backup over the exact data file, and restart the same V3.2 image. This is a recoverable data replacement, not a general cleanup operation:

```text
/DATA/AppData/pubg-query-engine-v3/backups/features-before-compaction-20260903.json
→ /DATA/AppData/pubg-query-engine-v3/data/features.json
```

Before any replacement, make a fresh copy of the current `features.json`. Never use a broad recursive delete.
