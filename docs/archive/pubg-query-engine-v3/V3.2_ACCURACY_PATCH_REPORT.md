# V3.2 ACCURACY PATCH REPORT

更新时间：2026-09-03（Asia/Shanghai）

本次是基于 V3.2 初版的 correctness patch。V3 QuerySubgraph、V3.1 Platform Adapter 和原有 ReviewSubgraph 接口均保留；只修正事实边界、团战聚合、点评和整活候选。

## Root Causes

- `rideDistance` 被错误地当成了 `driveDistance`，且未确认 `seatIndex` 的 driver 映射。
- 缺失或无效事件时间被下游显示逻辑归一成了 `00:00`。
- Fight Detector 过去把全局 combat event 混入 tracked team，且没有严格按最终击杀、DBNO 和 attack/dBNO 关联去重。
- 没有在渲染前验证团战聚合与 Match Store 总量，错误聚合可以直接进入点评。
- KeyOperation 和 Player Commentary 对普通载具移动及每人必夸存在过度推断。
- 趣味输出来源过窄，且火箭发射数可能误用 `LogWeaponFireCount.fireCount`。

## Fight Detector Fix

- 以共享 `default_team` 为视角，只接受 `trackedTeam ↔ opponent` 的 DAMAGE、KNOCK、KILL 和同队 REVIVE；`otherTeamA ↔ otherTeamB` 会被忽略。
- Fight seed 来自 tracked player 对敌、敌对 tracked player 的相关 combat event；相关事件超过 28 秒无活动就结束当前 Fight，后续交战新建 Fight。
- `teamKills` 只统计 tracked attacker 对 enemy victim 的最终 KILL；`teamKnocks` 只统计 `LogPlayerMakeGroggy` 的 tracked attacker → enemy victim。
- 通过 `victimId`、`dBNOId`、`attackId`、`accountId` 和 team scope 去重；每个 normalized combat event 只归属一个 Fight。
- 展示使用我方视角：我方击杀/伤害/倒地与承受伤害/倒地，不再展示未经范围过滤的全服总量。

## Fight Integrity Validation

新增 `FightIntegrityValidator`，在 Review Facts 完成后验证：

- 所有 Fight 的 kills、knocks、damage 不超过 Match team totals（damage tolerance 为 1）。
- 单 player 的 Fight kills、knocks、damage 不超过该玩家 Match Store 数据。
- Fight evidence 存在、只包含相关事件、声明指标与 evidence 重新计算值一致，且没有事件跨 Fight 重复归属。

失败时 Facts 标记为 `FIGHT_ANALYTICS_INVALID`，Review Analyzer 不生成团战结论或依赖无效 Fight 的高光；Renderer 只显示“详细团战数据未通过一致性校验，暂不展示”。完整 diagnostics 会保留在 trace。

## Vehicle Semantics Fix

- 保留 `rideDistance`、`driveDistance`、`driverConfirmed`、`passengerConfirmed`、`maxSpeed`、载具伤害和摧毁数等独立字段。
- `seatIndex` 会被保留，但没有在没有真实来源确认时硬编码 driver seat mapping；只有 telemetry 明确给出 driver/isDriver 等字段才累计 `driveDistance`。
- 无法确认 driver 时只渲染“乘车 X km”；距离本身不创建 KeyOperation。载具伤害、摧毁、击杀或其他有证据的高影响行为才可创建载具操作。
- Vehicle 行为只在有 evidence 时显示；没有 vehicle event 不显示空载具行。

## Timestamp Fix

事件优先使用真实相对游戏时间或可验证的绝对时间与 Match 起始时间差。无法可靠得到时间时保存 `null`，Operation 渲染省略时间；不会再把缺失时间变成 `00:00`。

## Commentary Fix

- Player Commentary 以 evidence-backed KeyOperations、通过完整性校验的 Fight Facts 和 Match Facts 为依据，不以 rideDistance 或单独击杀数推导“载具运营贡献”。
- `matchRole` 改为 optional，并同时保存 `roleConfidence`；证据不足时不显示 Role。
- 玩家可以得到 positive、neutral、low participation 或 evidence-backed negative 评价。0/0/0/0/低伤害且无操作时可以说“本局未检测到有效关键贡献”；存在 1 kill/knock 等事实时不会说成毫无贡献。
- “做得好的 / 可以改进 / 本局关键人物”只从真实 Fight、KeyOperation、revive 或 SpecialEvent 生成；没有证据时使用保守占位或省略。

## Fun Generator

新增 `FunCandidateGenerator`，先生成 deterministic facts，再要求每个候选拥有可解析的 `ReviewEvidence.id`，最后按 impact score 稳定排序并限制为 2~5 条可用候选。Section 名称统一为 `🤣 本局整活`。

首批候选包括 `ROCKET_UNUSED`、`ROCKET_MISS`、`ROCKET_MULTI_KILL`、`ROCKET_VEHICLE_MULTI_KILL`、`TOP_DRIVER`、`TOP_PASSENGER`、`LONGEST_RIDE`、`MOST_REVIVES`、`MOST_ASSISTS`、`HIGH_KNOCK_LOW_CONVERSION`、`NO_COMBAT_PRESENCE`、`HIGH_DAMAGE` 和 `LOW_DAMAGE`。长距离乘车只能产生乘车类事实，不能变成驾驶贡献。

Panzerfaust shot count 使用 `LogPlayerAttack + attackId` 去重，不把 `LogWeaponFireCount.fireCount` 当作精确发射数。`ROCKET_HIT`、载具多杀等事件要求相应 attack/vehicle/kill evidence；时间接近本身不会产生“一炮四杀”。
