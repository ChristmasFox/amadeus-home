# PUBG V3.2 — Review Schema

## Canonical Query Extension

V3.2 keeps `version=3` and adds an optional `matchSelector`. Only an explicit review intent or an active review follow-up may produce `operation=review_match`.

```json
{
  "version": 3,
  "domain": "pubg",
  "operation": "review_match",
  "selector": {"type": "relative_period", "value": "yesterday", "label": "昨天"},
  "matchSelector": {"type": "ordinal", "ordinal": 3},
  "subject": {"type": "team", "ids": ["default_team"]},
  "groupBy": "match",
  "metrics": ["matches", "kills", "assists", "damage"],
  "orderBy": {"metric": "damage", "direction": "desc"},
  "limit": null,
  "segments": [],
  "filters": {"competitiveOnly": true},
  "reference": {"selectorExplicit": true, "subjectExplicit": false, "planner": "deterministic_fallback"},
  "presentation": {"profile": "default", "compact": false}
}
```

## Match Selectors

| Selector | Meaning |
| --- | --- |
| `latest` | newest candidate; `recent=true` records “刚才/最近” intent |
| `earliest` | oldest candidate |
| `ordinal` | Nth candidate in stable `startedAt ASC` order |
| `ordinal_from_end` | Nth candidate from newest |
| `filtered` | deterministic filters such as `{ "placement": 1 }` |
| `ranked` | rank candidates by `teamDamage/teamKills/teamAssists/placement/duration` |
| `active_match` | current sender's active reviewed Match |
| `previous` / `next` | neighboring candidate by active ordinal |

Examples:

```text
帮我复盘今天             → review_match + no matchSelector → Picker when multi-match
复盘今天最后一把         → latest
复盘刚才那把             → latest(recent=true)
复盘昨天第三把           → ordinal(3)
复盘昨天吃鸡那把         → filtered({placement: 1})
复盘今天伤害最高那把     → ranked(teamDamage, desc)
```

`last_n_matches` belongs to the period selector, not the match selector. The resolved ResultSet is always ordered ASC for ordinal stability, even when the source repository is newest-first.

## Resolution Statuses

| Status | Meaning |
| --- | --- |
| `MATCH_NOT_FOUND` | no candidate or requested ordinal is out of range |
| `MATCH_SELECTION_REQUIRED` | more than one candidate remains; no automatic choice |
| `OK` | one Match selected and review facts are available |
| `REVIEW_PARTIAL` | base Match exists but telemetry is unavailable |

## Selection Token

Telegram `callback_data` is `pubg:m:<short-token>`. It never contains the full PUBG `matchId`. The persistent Selection Store records:

```ts
interface MatchSelectionRecord {
  token: string;
  platform: string;
  chatId: string;
  sessionId: string;
  matchId: string;
  resultSetId: string;
  ordinal: number;
  createdAt: string;
  expiresAt: string;
  query: CanonicalQuery;
}
```

Callback resolution is deterministic and requires matching platform, chat ID and non-expired token. The clicking member does not need to be the member who requested the Picker; group review is read-only.

## Review Profiles

`default`, `combat`, `weapon`, `vehicle`, `personal`, `fun`, and `detailed` are presentation hints. They do not change Facts or detector semantics. A profile can select Sections without adding a second telemetry parser.
