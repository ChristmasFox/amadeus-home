# PUBG V3.2 — Review Subgraph Architecture

## Shared Prelude

```text
Telegram / KOOK event
        ↓
Platform Adapter → NormalizedBotMessage
        ↓
Identity Registry
        ↓
sender-scoped Context Store
        ↓
Planner
        ↓
CanonicalQuerySchema validator
        ↓
Time / Selector Resolver
        ↓
Operation Router
        ├─ report/rank/strongest/weakest/compare/trend/detail/list
        │      → V3 QuerySubgraph → Match Store → ResultSet → Renderer
        └─ review_match
               → V3.2 ReviewSubgraph
```

ReviewSubgraph does not own a second identity, time parser, default team, Match Repository or platform session implementation. Both subgraphs receive the same `CanonicalQuery`, `DataLayerResult`, Context and normalized platform message.

## Review Flow

```text
Resolve period
    ↓
Resolve candidate Matches (startedAt ASC)
    ├─ 0 → MATCH_NOT_FOUND
    ├─ 1 → direct review
    └─ N → MATCH_SELECTION_REQUIRED → Picker + pending Context
                                      ↓ Telegram callback
                              short token → Selection Store
                                      ↓ same chat / expiry check
                              deterministic matchId resume
                                      ↓
                              Ensure Telemetry
                                      ↓
                              Review Facts → Analysis → Sections
                                      ↓
                              Telegram/KOOK Platform Renderer
```

The Picker path never calls `TelemetryWorker`. The worker is called only after the selected Match is unique. Telegram callbacks are ACKed by the plugin before the potentially slow resume request.

## Module Responsibilities

| Layer | Implementation | Responsibility |
| --- | --- | --- |
| Shared | `src/context`, `src/platform`, `src/time`, `src/schema` | identity, sender isolation, time, selectors, validation, contracts |
| Query | `src/engine`, existing renderer paths | V3 aggregation, ranking, compare, trend, Chicken Index |
| Review routing | `src/runtime/workflow.ts` | operation branch, Picker state, callback resume, active Context |
| Match selection | `src/review/match-selector.ts` | period candidates, ordinal, latest, ranked and filtered resolution |
| Telemetry Worker | `src/review/telemetry.ts` | API/download, gzip decode, cache, extraction boundary |
| Event normalization | `src/review/telemetry-events.ts` | raw PUBG event to normalized event conversion |
| Facts | `src/review/review-facts.ts` | structured Match/Squad/Player/Fight/weapon/vehicle facts |
| Detectors | `fight-detector`, `key-operation-detector`, `special-events` | deterministic derived facts with evidence IDs |
| Presentation | `src/review/presentation.ts` | extensible overview/player/fight/conclusion Sections |
| Platform renderer | `src/platform/core/renderer.ts` | message length, buttons and platform-specific response envelope |

## Data Direction

```text
PUBG Match Store ───────────────→ QuerySubgraph
                  └─────────────→ ReviewSubgraph (base summary)
PUBG Telemetry API → TS Worker → Review Facts → Review Analyzer
n8n                → Data Gateway/Sync and external retry/integration only
Mastra             → workflow/orchestration and optional structured planning
```

Raw telemetry is scoped to the Worker. It is never placed in the planner prompt, Context, ResultSet rows, or platform response. Persisted Feature Store records contain derived facts and evidence references; the transient normalized stream is discarded after extraction.

## Failure Boundary

If the base Match exists but telemetry download or parsing fails, the ReviewSubgraph returns `REVIEW_PARTIAL`, keeps the Match summary, and renders an explicit warning. It does not convert a telemetry failure into `MATCH_NOT_FOUND` or `NO_MATCHES`.
