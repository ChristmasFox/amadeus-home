# M204 native Qwen3-TTS service (1.5.3 candidate)

A single resident official `Qwen3-TTS-12Hz-1.7B-Base` model and reusable `kurisu-v1` clone prompt. This is an inference boundary, not an Agent or speech planner. Python dependencies are pinned in `requirements.txt`; model weights and profile are outside Git.

Provision an operator-owned, licensed `reference.wav` (short clean speech) and matching `reference.txt` in `~/Library/Application Support/Amadeus/voices/kurisu-v1/`, both mode 600. Do not commit either file or generated embeddings. `manage-qwen3-tts.sh --prepare-apply` creates `~/Library/Application Support/Amadeus/speech/tts.token` mode 600 if absent (never prints its value); then configure 9Router's Self-hosted TTS provider with the same secret outside Git. Endpoint for the OrbStack guest: `http://host.docker.internal:18792/v1`, model `qwen3-tts-1.7b`, voice `kurisu-v1`. `GET /healthz` is public and exposes only readiness/model/voice identifiers; speech and voice inventory require Bearer auth.

`infra/macos/manage-qwen3-tts.sh --dry-run` is safe by default. `--prepare-apply` installs the venv and downloads the upstream model at pinned Hugging Face revision `fd4b254389122332181a7c3db7f27e918eec64e3` without starting a service. `--apply` requires the prepared model/profile/token and installs the source and launchd user agent; `--status` checks the service, `--uninstall` stops it without erasing weights, voice, or token. A user LaunchAgent is required for Metal/MPS access. `ThrottleInterval=60` bounds crash restarts. Model files are under `~/Library/Application Support/Amadeus/speech/model` and cache under `speech/model-cache`; sanitized rotating logs are under `~/Library/Logs/Amadeus/qwen3-tts.log` (2 MB + 3 backups). Reboot recovery assumes the user's launchd session starts (as with MacHostAgent).

Warmup performs actual synthesis before ready. Requests are serialized at the engine and limited to 1200 Unicode codepoints / 8 KiB JSON / 12 MiB WAV, with a 30-second format-conversion timeout. OpenAI-compatible `response_format` supports `wav`, `mp3`, and `opus` (48 kHz Ogg/Opus). No request text or reference bytes are logged; no media files are retained by this service. OpenClaw handles inbound temporary media and synthesized-media retention separately.

Test locally without downloading weights: `python3 -m unittest discover -s apps/qwen3-tts-service/tests -v`. Real MPS synthesis, profile quality, Docker-to-host routing, 9Router integration and WhatsApp acceptance are **not** asserted by the unit tests.

## 9Router provisioning (pending live credentials and ASR smoke)

`scripts/provision-9router-speech.py` defaults to dry-run. The upstream model uses DashScope multimodal-generation, not multipart STT. A bounded protocol adapter in the 9Router image exposes local multipart STT at `127.0.0.1:20129`; its external DashScope key and region/workspace URL live only in the guest's protected secret mount and `9router.env`. Use `--apply` with protected 0600 `--dashboard-password-file`, `--asr-key-file` (bridge Bearer token) and `--tts-key-file` (M204 TTS token). It logs in only over M204 loopback, captures an online SQLite plus compose/env/image rollback checkpoint in the guest, creates/reuses self-hosted STT/TTS connections, retires the conflicting old `amadeus-asr` Chat Combo and provisions the stable aliases. Existing mismatched connections/aliases fail closed; the script never prints secrets. The ASR bridge independently survives an M204 TTS service outage. A valid response still requires **direct audio and normalized transcript smoke** before applying the OpenClaw config. Do not run the live path until direct DashScope Qwen-Audio-3.0-ASR-Flash output shape and route auth are verified.
