# Amadeus 1.7.7 private image-generation attempt — reproduced failure

Date: 2026-10-01 (Asia/Shanghai)
Status: `SUPERSEDED_BY_1.7.8_AFTER_OWNER_RETRY_FAILED`

## Initial incident and deployment

A read-only, field-allowlisted audit of one owner private WhatsApp turn found an
accepted detached `image_generate` task whose model-authored params included
`model=openai/gpt-image-2`, overriding operator-configured
`openai/amadeus-image`. The OpenAI-compatible provider returned HTTP 400
`invalid_request_error`, code `bad_request`; the turn's Chinese input also had
`request_language=unknown`. The 9Router fallback is attached to logical
`amadeus-image`, so a concrete model override was a plausible bypass.

Commit `79577cc` deployed as
`local/openclaw-amadeus:git-79577cc27dfc-20261001110629`, image ID
`sha256:49e61f1b201cad76b1db139993260f75d7f5163269478b688556d082e5598e14`;
runtime `1.7.7` and automated gates were healthy. The initial
`before_tool_call` policy returned params without the `model` field.

## Owner retry and why 1.7.7 did not fix it

The owner retried private image generation after 1.7.7 and saw the same failure.
Content-safe runtime evidence showed the policy warning fired, but the exact
pinned OpenClaw 2026.9.4 hook implementation shallow-merges returned params over
the original object. Omitting a key therefore preserved the model override. The
tool result again reported `openai/gpt-image-2`, and the provider returned HTTP
400. No rollback was performed.

The retry's task requester session hash matched the inbound WhatsApp session
hash. The lifecycle still reported `request_language=unknown`; source review
then found request capture used `event.body ?? event.content`, so a present but
blank `body` prevented fallback to non-empty normalized `content`.

The 1.7.8 follow-up fixes both confirmed gaps: it sets `model` to an empty
string (valid tool schema, treated as no override by native parsing) so the host
merge cannot preserve the concrete model, and selects the first non-empty
`body`/`content` string for request-language capture. See
`.agent/checkpoints/2026-10-01-amadeus-1.7.8-image-route-repair.md` for follow-up
deployment evidence.

No private prompt/message/image contents are retained. The provider's 400 did
not expose a safe `param` value, so the precise provider-rejected field is not
claimed beyond the reproduced model-override path.
