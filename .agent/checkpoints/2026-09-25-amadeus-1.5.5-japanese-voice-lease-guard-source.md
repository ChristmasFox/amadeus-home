# 2026-09-25 — Voice language rule: actual hook boundary and fail-closed audio guard (source)

## Read-only diagnosis

- Owner reported an unsolicited Chinese PTT; the latest voice turn did not ask for Chinese. Sanitized transcript metadata showed a Chinese-only assistant final, with no `日本語：` line and no `[[tts:text]]`. No message/audio contents were persisted in Git.
- Live SOUL.md and USER.md have a Simplified-Chinese preference for ordinary text. That preference is not itself a voice-rule conflict: the voice Skill is supposed to override it on verified voice turns.
- Pinned `@openclaw/whatsapp@2026.9.4` monitor source makes plugin `message_received` opt-in (`channels.whatsapp.pluginHooks.messageReceived` defaults to false), and suppresses the core fallback hooks. Live config has no global or account opt-in. Both earlier runId/sessionKey trackers waited on a hook that was never fired. The voice Skill was not injected, leaving the ordinary Chinese default in force.

## Source fix

- Removed the dead `message_received` tracker/cleanup path from `plugins/amadeus/src/voice-reply-prompt.ts`.
- `before_prompt_build` now uses the existing process-global WhatsApp active voice lease, created only for admitted audio before Agent dispatch and released after full delivery (or the 120-second safety limit). The platform/channel and exact session key are checked. Typed-only turns have no lease and retain existing behavior.
- Upgraded the mounted WhatsApp monitor's visible-text helper with a new versioned Japanese-audio guard. If a verified inbound voice turn produces a TTS/PTT attachment whose `spokenText` has no Japanese kana (or no spoken source), the prepared payload loses audio media/TTS metadata and delivers text-only with a Japanese-voice-unavailable notice. This prevents the observed Chinese-only audio from being delivered even if the model still omits the Japanese directive. It is a conservative fail-closed script check, not a general language classifier or translator.
- No second sender/Agent/planner, broad message content hook, SOUL/AGENTS workflow text, or typed-only behavior change was introduced.
