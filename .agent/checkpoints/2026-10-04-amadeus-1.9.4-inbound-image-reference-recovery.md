# Amadeus 1.9.4 inbound image reference recovery checkpoint

Date: 2026-10-04 (Asia/Shanghai)
Status: complete

## Trigger

A private WhatsApp image message around 02:52 was downloaded successfully and
included in the model context. The following `image_generate` call used a
malformed model-authored inbound staging path: it referenced
`openclaw-staged-abfbb217c172-...`, while the canonical staged directory was
`openclaw-staged-abfbb217-c172-...`. Native media loading therefore failed with
`Local media file not found`. This was a path-reference corruption after image
ingress, not a failure to receive or expose the image to the model.

## Source change

- Source commit: `5c738c9` (`fix(amadeus): rebind inbound image references`).
- Release: `VERSION=1.9.4`.
- `plugins/amadeus/src/image-assets.ts` records the first current inbound image
  path at `message_received` and binds it into the current image context at
  `before_dispatch` with a short TTL.
- A `before_tool_call` hook for `image_generate` repairs only parameters whose
  model-supplied value contains `/media/inbound/`, replacing it with the current
  canonical inbound path and de-duplicating image arrays.
- Durable generated-image paths are unchanged. The hook logs only safe run/tool
  metadata and never logs image bytes or filesystem paths.
- Added pure regression coverage for malformed inbound references and for
  preserving durable generated paths.
