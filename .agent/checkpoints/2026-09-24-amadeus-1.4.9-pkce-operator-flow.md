## Source correction

The Longbridge OAuth operator path now follows the current public-client flow:

```text
LONGBRIDGE_OAUTH=oauth2
LONGBRIDGE_PKCE=S256
LONGBRIDGE_SCOPE=3
LONGBRIDGE_CALLBACK_STATE=validated
OAUTH_REQUEST_STATE=external-0600-and-deleted-after-exchange
OAUTH_SECRETS=not-printed-and-not-committed
```

The authorization URL includes `scope=3`, `code_challenge`,
`code_challenge_method=S256`, and a random state. The exchange helper accepts a
complete callback URL from stdin, checks its state against the external
request record, sends the verifier only to Longbridge, persists token state at
the external 0600 state path, and removes the short-lived request record.
