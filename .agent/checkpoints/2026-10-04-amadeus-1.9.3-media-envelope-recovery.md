# Amadeus 1.9.3 media envelope recovery checkpoint

Date: 2026-10-04 (Asia/Shanghai)
Status: complete

## Trigger

A group image/upscale run (`ac1667...`) completed the image operation and
registered asset `img_a474eade27b444d79251da157b038fb2`, but the model returned a
legacy `MEDIA:/var/lib/amadeus/...png` path on the first line followed by a valid
DeliveryEnvelope v2 JSON object. The strict decoder parsed the whole response,
logged `invalid_structured_output`, and sent `回复格式异常，已记录，请稍后重试。`
alongside the attachment. The attachment was already selected from the
runtime-owned completion claim; the path was never a valid asset authority.

## Source change

- Source commit: `e2a94af` (`fix(amadeus): accept legacy media-prefixed envelopes`).
- Release: `VERSION=1.9.3`.
- `plugins/amadeus/src/delivery-decoder.ts` now accepts only the exact legacy
  first-line `MEDIA:` prefix when the remaining payload begins with a JSON
  object, discards the path, and validates the remaining typed envelope with
  the existing strict validator.
- The path cannot populate an asset id, storage key, caption, or attachment;
  runtime-registered completion assets remain authoritative.
- Added a regression test proving the envelope is retained and the path is not
  present in the decoded delivery.
