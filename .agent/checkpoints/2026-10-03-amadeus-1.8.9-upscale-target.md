## Cause

Recent private-chat upscale tool calls put inbound staged filesystem paths or
filenames such as `/home/node/.../input-*.png` into `target.imageId`. The image
service accepts only canonical registry IDs matching `img_[0-9a-f]{32}`, so it
returned `image_id_invalid` before any upscale work started. The failure was in
input target selection, not ESRGAN/model processing.

## Fix

Amadeus now forwards `imageId` only when it matches the canonical registry ID
format. Invalid model-authored paths and filenames are omitted, allowing the
existing `replyMessageId` and `conversationId` resolver to select the private
reply image or the most recent image in the current conversation. Explicit
canonical IDs remain authoritative. A regression covers the staged-path case.
