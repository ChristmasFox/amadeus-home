# Amadeus 1.4.9 OAuth and glibc runtime checkpoint

Date: 2026-09-24 (Asia/Shanghai)

## External operator state

- Longbridge OAuth client was dynamically registered with the fixed local callback
  `http://127.0.0.1:18792/callback`; the client id is stored only in the protected
  CasaOS secret path and is not recorded here.
- PKCE browser authorization and code exchange completed on M204. The canonical
  OAuth state and official SDK token cache were copied with runtime ownership and
  `0600` permissions under `/DATA/AppData/openclaw/data`.
- The user-level `com.amadeus.machostagent` LaunchAgent is installed. A bearer-
  authenticated local HostAgent health request returned HTTP 200.
- Callback URL, access token, refresh token and client id are excluded from this
  checkpoint and from Git.

## Runtime boundary

- Direct import of `longbridge@5.1.0` in the pinned OpenClaw Debian 12 image
  failed because the ARM64 native binding requires `GLIBC_2.39` while the base
  image supplies glibc 2.36.
- The Dockerfile now downloads the SHA-256-pinned Ubuntu 24.04 `libc6` 2.39
  package for the target architecture, keeps it under `/opt/amadeus-glibc`, and
  runs the Node binary through a private loader wrapper. The system libc is not
  replaced.
- ARM64 build tag tested: `local/openclaw-amadeus:glibc39-20260924210323`.
  Image manifest digest: `sha256:9a1af64853066bd1298899fd524cda3b4d5cfcf94925142ba7a2f6ebc90af664`.
  Node 24 startup and `longbridge` SDK import both passed in the built image.

## Remaining acceptance

- The live CasaOS container has not yet been switched to this image. Release
  build, protected rollback checkpoint, restart persistence, live quote/session,
  host telemetry and owner notification smoke remain pending.
- `scripts/longbridge-oauth-authorize.mjs` now reads `/dev/stdin` for Node 24
  compatibility. The exchange was run with `NODE_USE_ENV_PROXY=1` because Node's
  built-in fetch does not otherwise consume the M204 proxy environment.
