## Change

A successful ordinary `image_generate` imports the trusted OpenClaw generated
attachment into the Asset Registry before native completion continues. The
native completion handoff keeps the exact `image_generate:<taskId>` provenance,
passes verified image bytes as read-only model context, and carries that context
through the durable `session_queued` path. The completion path waits for a
queued Completion Agent instead of treating it as an immediate failure. The
Completion Agent's one v2 text part is bound to the existing inline attachment
caption; Amadeus performs the one channel image send. A true failure, malformed
reply or timeout uses the idempotent attachment-only fallback.

Unrelated inter-session turns remain silent. Native task completion remains
live, and native `attachments`/`mediaUrls` are removed before the native route
can send media, preventing duplicate image delivery. Text, voice/TTS/ASR,
upscale/document and reference-image routes were not changed.
