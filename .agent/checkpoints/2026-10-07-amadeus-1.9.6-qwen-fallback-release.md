# Amadeus 1.9.6 — cloud primary with local Qwen fallback

The operator requested formal production deployment after confirming the
strength-corrected local pose edit looked acceptable. Release commit
`e7a815c` advanced Amadeus to 1.9.6 and removed the retired Krea2 bridge,
tests, LaunchAgent template, engine config, active Compose mount, and deploy
script token injection. External Krea model files were not deleted.

The release used the existing protected Qwen bridge and preserved the
primary-only 9Router contract:

```text
primary: cx/gpt-image-2.5 via 9Router
eligible operational primary failure: one OpenClaw-owned local Qwen attempt
zero references: /v1/images/generations
one reference: /v1/images/edits with validated original bytes/MIME
primary safety refusal or invalid request: terminal; no local fallback
```

## Acceptance boundary

The release is live, but the Goal is **not complete**. The user's visual
acceptance covered local-only candidate image edits; a post-release WhatsApp
reference edit that first fails on GPT Image and then visibly succeeds through
the Qwen fallback has not yet been run. The healthy-primary path likewise has
not been verified by live fault-injection evidence. Do not claim end-to-end
fallback acceptance until those WhatsApp checks prove one edited image, one
caption, and no duplicate completion message.

Rollback target remains the protected pre-switch backup and the prior
immutable OpenClaw image recorded there. 9Router, Product Radar, voice/TTS/ASR,
and external Qwen model assets were not changed by the release.
