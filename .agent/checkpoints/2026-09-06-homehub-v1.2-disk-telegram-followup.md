# HomeHub V1.2 Follow-up: Disk Capacity and Telegram Outbound Fallback

- Date: 2026-09-06 (Asia/Shanghai)
- User request: show NAS disk used/total/free capacity; Telegram stopped replying.

## Diagnosis

LangBot logs contained:

`telegram.error.BadRequest: Can't parse entities: can't find end of precode entity at byte offset 2351`

The Telegram adapter was receiving malformed Markdown/code-fence content. The container and
Telegram adapter were alive; subsequent messages showed successful outbound sends, so this was
an outbound entity parsing failure rather than a Docker/container outage.

## Changes

- HomeHub/NAS status disk rows now render `used / total`, `available`, and `usage percentage`
  with a warning at 90%+. The APFS root calculation remains `total - available` to avoid the
  macOS snapshot `df` Used-column issue.
- The tracked Telegram patch now retries entity-related `BadRequest` for outbound text/photo/
document/edit operations as plain text after removing `parse_mode`, `entities` and
`caption_entities`. Unrelated `BadRequest` errors still fail normally.
- The patch is idempotent for already-patched LangBot source and preserves `pubg:m:` plus
  `hh1:` callback handling.
