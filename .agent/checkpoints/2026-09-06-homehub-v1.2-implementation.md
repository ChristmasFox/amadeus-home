# HomeHub V1.2 Source Implementation Checkpoint

- Date: 2026-09-06 (Asia/Shanghai)
- Scope: HomeHub V1.2 identity, confirmation UI, MacHostAgent, status UX and Service Registry.
- Git source is the only source of truth; no runtime secret was added.

## Implemented

- Telegram normalized identity uses `message.from.id`; callback identity uses `callback_query.from.id`; chat uses `message.chat.id`. LangBot event normalization now recovers the raw Telegram Message/Update when legacy `sender_id` equals the group ID. KOOK continues to use `author_id`/sender ID.
- Confirmation is rendered through the existing platform-neutral presentation and Telegram PUBG inline keyboard path. `hh1:confirm:<actionId>` / `hh1:cancel:<actionId>` callbacks are checked against platform, chat, user and action ID. Pending actions claim atomically, expire after the configured TTL, and clear after execution/cancel.
- `/v3/route` and `/v3/query` route HomeHub text confirmations and HomeHub callbacks before PUBG handling; PUBG callback namespace remains unchanged.
- Added `MacHostAgentCommandExecutor` and read-only `infra/macos/mac_host_agent.py`; only three authenticated GET endpoints exist. Host collection returns UNKNOWN when the agent/token/connection is unavailable and never uses container `/proc` metrics.
- MacHostAgent disk accounting matches the NAS formatter for APFS root snapshots (`total - available`), and collects network, power, cloudflared and high-CPU process data.
- Registry maps actual CasaOS/Compose labels: `postgres` to `immich-postgres` (`immich/database`) and `redis` to `immich-redis` (`immich/redis`); `media-organizer-adapter` is registered.
- Health status prioritizes executor/alive/Docker health/application endpoint and treats recent log errors as DEGRADED evidence only. The status formatter groups NAS, core, media and infrastructure services and emits a focused attention list.
