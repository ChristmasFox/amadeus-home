# 2026-09-25 — Consecutive WhatsApp group voice TTS regression and ingress-queue fix

## Observed evidence

- Owner reported two group voice notes sent consecutively; one returned a PTT, the other text only.
- A body-free 20-minute OpenClaw log read showed two `audio/ogg` inbound events at 12:18:40Z and 12:19:00Z, two assistant final transcript turns, and one `Sent media reply` event. No body, group JID, phone number, or raw WhatsApp ID is stored here.
- The user-turn timestamps were about 10 seconds apart. A later transcript commit for the queued input occurred after the first response, consistent with serialization.

## Diagnosis

In pinned OpenClaw 2026.9.4, `sendFollowupPayloads()` delivers same-origin followup results with direct `routeReply()`. That function normalizes and sends the payload but does not invoke the normal dispatch final-TTS application. The ordinary inbound path goes through `dispatch-from-config`, which calls `maybeApplyTtsWithFinalizationLease`. Thus an audio reply that is diverted to the core followup queue may preserve its text/TTS directive metadata but skip audio synthesis. This explains the one-PTT/one-text-only symptom; the timeline and code path make this a strong diagnosis.

## Fix source, not yet deployed

- New `runAmadeusWhatsAppVoiceScopedIngress()` serializes arrivals at WhatsApp `processForRoute` only while a same-session voice lease or its FIFO tail is active.
- Each queued voice then enters a separate normal `processMessage` -> `runChannelInboundEvent` -> `dispatch-from-config` TTS path, rather than the core followup `routeReply()` path. Later same-session text remains FIFO behind the queued voice.
- Each audio run gets its own 3-second composing lease and 120-second cap. Presence failure stops the keepalive but does not release ordering early; full turn settlement, disconnect and timeout clean up.
- Ordinary typed-only sessions/concurrency bypass this queue.
- Tests now exercise two queued voice turns plus later text in strict order and verify normal inbound dispatch is used. Full `pnpm test`, `pnpm typecheck`, architecture, secrets, exact pinned monitor patch, syntax, idempotency and deployment-stdin invocation pass.
