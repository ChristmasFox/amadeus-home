# Amadeus 1.9.2 upscale recovery checkpoint

Date: 2026-10-04 (Asia/Shanghai)

## Trigger and diagnosis

- The host registry recorded a plain 2x request from `853x1843` with a
  model-authored `resolution=2k`; the derived result was `1185x2560`, which
  reflected the 2560px long-edge profile cap rather than an exact 2x result.
- A following 4x request from `1185x2560` with `resolution=4k` ended in
  `status=failed`, `error=upscale_failed`, before a ready asset was written.
  The un-tiled x4 MLX path allocated a large discarded intermediate tensor.
- The source originals and prior derived assets were preserved; no asset bytes
  were deleted or overwritten.

## Source changes

- Commit `8e667cf` (`fix(amadeus): make upscale multipliers exact and memory safe`).
- `plugins/amadeus/src/image-assets.ts` now forwards resolution only when the
  current user turn explicitly contains 2K/4K. Plain multiplier requests keep
  exact dimensions even if the model fills the optional resolution field.
- `apps/amadeus-image-service/service.py` passes the deterministic target size
  into the engine, uses a bounded x2 inference path for capped 4x profiles,
  records `engineScale`, and defaults the MLX tile size to 256.
- Host profile and launchd source now declare `AMADEUS_IMAGE_TILE=256`.
- Version `1.9.2` and release notes were updated; focused TypeScript and Python
  regressions were added.
