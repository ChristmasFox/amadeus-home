## Scope completed

- Added platform-neutral `AuthorizationCore` with `PlatformIdentity -> InternalIdentity -> Role -> Authorization`.
- Identity mappings use only `platform + platformUserId`; inbound internal IDs and display names are not trusted.
- `TELEGRAM_ADMIN_USER_ID` and `KOOK_ADMIN_USER_ID` map to `arthur` / `ADMIN`; examples remain empty placeholders.
- HomeHub Action and media organize paths require allowlisted policy, risk evaluation, explicit confirmation, execution, and verification.
- Pending confirmations are bound to platform, chatId, platformUserId, and actionId. A different group member cannot confirm or cancel another user's action.
- Audit entries include platform, platformUserId/userId, internalUser, role, action, target, authorized/denied, result, timestamp.
- Added explicit runtime executor abstraction for Docker, Ubuntu, macOS Host, and LangBot Component boundaries.
- Service Registry now declares runtime/executor for all 13 HomeHub services. `cloudflared` is a macOS Host service and returns UNKNOWN without a Host Executor.
- Replaced HomeHub remote `orb -m` command paths with direct executor commands (`docker`, `pgrep`, `curl`, etc.).
- Health semantics now distinguish healthy, unhealthy, down, and unknown. Executor/observation failures are UNKNOWN and excluded from `abnormal`.
- Host CPU/memory/disk collection returns null metrics when unavailable; no failure fallback to 0%.
- organize-emby plugin requests the shared `/homehub/authorize` endpoint before Preview/Execute and keeps actor/action binding metadata.
