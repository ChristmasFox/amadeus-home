# Amadeus 1.8.5 image delivery timeout checkpoint

Date: 2026-10-02 (Asia/Shanghai)

## Change

Commit `73daf48` changes the Amadeus image-caption semantic deadline from 30
seconds to 120 seconds, with a 117-second provider budget that preserves the
existing one-second completion margin. The native OpenClaw completion overlay
now registers a typed Amadeus attachment fallback while native delivery is
`session_queued` or `completion_handoff_pending`. When the pinned 120-second
native handoff deadline expires, the overlay invokes that fallback once before
OpenClaw records the blocked continuation, so a generated image is delivered
rather than stranded.

Kurisu caption wording remains unrestricted from release 1.8.4: no Amadeus
character ceiling or short-caption target is added.

## Triggering evidence

The owner WhatsApp task
`1c85c388-e8a0-4531-82f3-8599226c7e79` generated and retained one image, but
its native Completion Agent continuation ended with `LLM request timed out`
and `Stream ended without finish_reason`. The continuation stayed pending
until the handoff deadline; the pre-fix recovery path could not send a
structured-only WhatsApp payload and the task became `blocked` with the media
retained. This checkpoint records the source-level fix for that failure mode.
